# 3MF files (`.3mf`): what MeshPeek reads

3MF is a published format ([3MF Consortium specifications](https://github.com/3MFConsortium/spec_core)). This note
covers what MeshPeek takes from it, and the slicer data next to the model that the specifications do not describe.
The reader is `crates/meshpeek-core/src/io/threemf.rs`.

## Package

A 3MF file is a ZIP package (Open Packaging Conventions). The model is the part named by the root relationship
(`_rels/.rels`, type `http://schemas.microsoft.com/3dmanufacturing/2013/01/3dmodel`), usually `3D/3dmodel.model`.
Part names compare without case.

## Core model

```xml
<model unit="millimeter">                       <!-- micron, millimeter, centimeter, inch, foot, meter -->
  <metadata name="Title">…</metadata>
  <resources>
    <basematerials id="5"><base name="red" displaycolor="#FF0000"/></basematerials>
    <object id="1" name="…" type="model" pid="5" pindex="0">
      <mesh>
        <vertices><vertex x="…" y="…" z="…"/>…</vertices>
        <triangles><triangle v1="0" v2="1" v3="2" pid="5" p1="0" p2="…" p3="…"/>…</triangles>
      </mesh>
    </object>
    <object id="2"><components><component objectid="1" transform="…"/></components></object>
  </resources>
  <build><item objectid="2" transform="…"/></build>
</model>
```

- An object holds a mesh or components (other objects, each with a transform). Each build item becomes one
  MeshPeek object; its components' meshes are merged into it.
- `transform`: twelve numbers `m00 m01 m02 m10 m11 m12 m20 m21 m22 m30 m31 m32`. Points are row vectors:
  `x' = x·m00 + y·m10 + z·m20 + m30`, and so on. A component's transform applies before its parent's.
- Objects of type `support` or `solidsupport` are shown as supports.
- Colours: `basematerials` (`displaycolor`) and the Materials extension's `colorgroup` (`color`), as `#RRGGBB` or
  `#RRGGBBAA` (alpha dropped). A triangle's `pid` and `p1`/`p2`/`p3` give a colour per corner; without them the
  object's `pid`/`pindex` apply. Textures are not read.

## Production extension

Bambu Studio and OrcaSlicer save every object in its own model file (`3D/Objects/object_N.model`). The root
model's objects consist of components with a `p:path` attribute naming that file. Items can carry `p:path` too.
MeshPeek reads the files the root model refers to in parallel.

## PrusaSlicer

- `Metadata/Slic3r_PE_model.config`: per object (`<object id>` = the object's id in the model), its name and
  extruder (`<metadata type="object" key="name|extruder" value>`), and its parts. Each part is a `<volume
  firstid lastid>` range of the object's triangles, with `key="extruder"` (0: the object's) and
  `key="volume_type"`: `ModelPart` is printed; `NegativeVolume`, `ParameterModifier`, `SupportBlocker` and
  `SupportEnforcer` are not, and MeshPeek leaves them out (older files: `key="modifier" value="1"`).
- `Metadata/Slic3r_PE.config`: the settings, as `; key = value` lines. The first line names the program
  (`; generated by PrusaSlicer 2.9.6 on …`). The colours are `extruder_colour` (`#RRGGBB;#RRGGBB;…`, empty
  entries allowed) and then `filament_colour`; the plate is `bed_shape` (`0x0,200x0,200x200,0x200`) and
  `max_print_height`. Build items are in plate coordinates (origin at the plate's corner).

## Bambu Studio and OrcaSlicer

- `Metadata/model_settings.config`: per object of the root model (`<object id>`), its name and extruder
  (`<metadata key="name|extruder" value>`), and its parts as `<part id subtype>`. The `id` is the object id of
  the component (in its own model file), and the part can carry its own `extruder`. `subtype` `normal_part` is
  printed; `modifier_part`, `negative_part`, `support_enforcer` and `support_blocker` are not. One `<plate>`
  element is written per build plate.
- `Metadata/project_settings.config` (JSON): `filament_colour` (`["#7D899B", …]`, one per filament),
  `printable_area` (`["0x0", "256x0", "256x256", "0x256"]`) and `printable_height`.
- Plates are laid out in a grid of `columns` = √plates rounded, plus one when √plates is above that; plate `i` is
  at row `i / columns` and column `i % columns`, moved by `(column · 1.2 · width, −row · 1.2 · depth)` (a gap of a
  fifth of a plate, Bambu Studio's `PartPlateList::compute_origin`). This matches every build item of the
  sample files to the plate `model_settings.config` puts it on.

## Painted colours (multi-material painting)

PrusaSlicer writes `slic3rpe:mmu_segmentation` and Bambu Studio / OrcaSlicer write `paint_color` on the painted
triangles (`paint_supports` and `slic3rpe:custom_supports` hold support painting, which is not shown). Both use
the serialisation of PrusaSlicer's `TriangleSelector`: a tree of subdivisions of the triangle, with a state on
each leaf.

- The value is hex digits, read **from the last** one. Each digit is a 4-bit code.
- Bits 0–1 of a code give the number of split sides (0 to 3).
- **Leaf** (0 split sides): bits 2–3 give the state; if they are `11`, the next digit gives the state minus 3.
  State 0 means not painted (the part's own extruder); state *n* means extruder (filament) *n*.
- **Split triangle**: bits 2–3 give the special side, and its children follow, **last child first**. With the
  corners turned so that the corner at the special index comes first (`a b c`) and `mid` the middle of a side,
  the children are:

  | Split sides | Children (in order) |
  |---|---|
  | 1 | `a b mid(bc)`, `mid(bc) c a` |
  | 2 | `a mid(ab) mid(ac)`, `mid(ab) b mid(ac)`, `b c mid(ac)` |
  | 3 | `a mid(ab) mid(ca)`, `mid(ab) b mid(bc)`, `mid(bc) c mid(ca)`, `mid(ab) mid(bc) mid(ca)` |

- Examples: `8` is a whole triangle painted with extruder 2, `0C` with extruder 3, and `841` a triangle halved
  once whose second half is painted 1 and first half 2.
- Every code of the sample files decodes exactly: 783,000 codes, 708 of them split, up to 5 levels deep.

## Colours in MeshPeek

A file whose printed triangles use one colour (or none) is shown in MeshPeek's own model colour. A file with
several gets them as vertex colours: slicer files from their parts' extruders and the painting, other files from
their colour properties. Triangles without a colour in a coloured file are light grey.
